- [x] **L'API mourait si Supabase devenait injoignable, au lieu de renvoyer une erreur.** L'appel `prisma.user.findUnique` de `backend/src/routes/auth.ts` était dans le callback de `jwt.verify` (`GET /me` et `PUT /me`), donc **hors de portée du middleware d'erreur Express** et d'`express-async-errors` : le callback s'exécute après que le handler a rendu la main, la promesse qu'il renvoie n'est attendue par personne, Node la classe en *unhandled rejection* et **termine le process** (comportement par défaut depuis Node 15). Constaté le 30 juillet 2026 : une coupure de quelques secondes du hotspot a tué l'API, qui est restée à terre. En production `restart: always` relance le conteneur, mais chaque occurrence coupe **toutes** les connexions Socket.IO. **Corrigé le 30 juillet 2026** (`fix/api-resiliente-base-injoignable`) : helper `decodeToken` utilisant la forme **synchrone** de `jwt.verify` (qui lève), accès base ramené dans le handler async donc sous le filet, + filet global `process.on('unhandledRejection')` dans `index.ts`. Prouvé sur une instance jetable pointée sur une base injoignable : 3 appels → 3 × 500 JSON propre, **process toujours vivant**, zéro trace de crash. Sémantique HTTP inchangée (401/403/404/200 vérifiés). Pas de handler `uncaughtException` volontairement : une exception synchrone laisse un état imprévisible, redémarrer est alors le bon comportement.
- [x] **Hello Marketing : musique du jour et actus RSS ne fonctionnaient QUE en local.** Les deux blocs passaient par `https://corsproxy.io`, un proxy CORS tiers, dont l'offre gratuite est réservée à localhost. Depuis l'origine de production le service répondait lui-même `403 {"error":"Free usage is limited to localhost and development environments"}`. La météo n'était pas touchée car OpenWeatherMap envoie ses propres en-têtes CORS et est appelée en direct. À noter : l'API Deezer n'envoie **aucun** `Access-Control-Allow-Origin`, elle est donc inappelable depuis un navigateur quel que soit l'environnement — le repli « appel direct » présent dans le code ne pouvait jamais fonctionner. **Corrigé le 30 juillet 2026** (`fix/feeds-proxy-backend`) : proxy maison `/api/feeds` + `/api/music/tracks`, avec registre de flux **côté serveur** (le client n'envoie qu'une clé, jamais une URL), cache mémoire, timeout 8 s et en-têtes de navigateur sortants.
