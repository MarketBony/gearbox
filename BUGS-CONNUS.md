- [x] **L'API mourait si Supabase devenait injoignable, au lieu de renvoyer une erreur.** L'appel `prisma.user.findUnique` de `backend/src/routes/auth.ts` était dans le callback de `jwt.verify` (`GET /me` et `PUT /me`), donc **hors de portée du middleware d'erreur Express** et d'`express-async-errors` : le callback s'exécute après que le handler a rendu la main, la promesse qu'il renvoie n'est attendue par personne, Node la classe en *unhandled rejection* et **termine le process** (comportement par défaut depuis Node 15). Constaté le 30 juillet 2026 : une coupure de quelques secondes du hotspot a tué l'API, qui est restée à terre. Prouvé sur une instance jetable pointée sur une base injoignable : 3 appels → 3 × 500 JSON propre, **process toujours vivant**, zéro trace de crash. Sémantique HTTP inchangée (401/403/404/200 vérifiés). Pas de handler `uncaughtException` volontairement : une exception synchrone laisse un état imprévisible, redémarrer est alors le bon comportement.
